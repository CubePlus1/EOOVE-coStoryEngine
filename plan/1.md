# 岁月史书 UI 改版拆分计划

目标仓库: `EOOVE-coStoryUI`  
当前技术栈: Vite + React + TypeScript + Motion  
目标方向: 从现有浅色纸本 UI 继续收敛为更克制的「岁月史书 · 浅米黄古籍」视觉，并逐步加入「流式落笔 + 自动翻页」机制。

## 原则

- 信息结构、路由 `?view=wall|phone|card`、mock 数据结构、轮询逻辑不作为视觉改版的一部分改动。
- 先统一展示数据，再做视觉，再做 FlipBook。不要把样式重构和复杂交互状态机混在一个提交里。
- 每一阶段都必须能独立 `npm test && npm run build`。
- 大屏端优先自动展示，不引入现场操作型交互。手机端再考虑手势和回看。

## Phase 1: 展示数据统一

目标: 消除 `App.tsx` 中大屏、手机世界流、我的故事三处各自映射 `Act` 的重复逻辑，给后续 FlipBook 一个稳定输入。

范围:

- 新增 `src/view-model/storyEntries.ts`。
- 从 `Act` 归一化出统一展示结构:

```ts
interface StoryEntry {
  id: number;
  round: number;
  title: string;
  text: string;
  chronicle: string;
  type: Act['type'];
  location: LocationId;
  involved: string[];
}
```

- 提供三个查询函数:
  - `getLocationStorySections(story, limitPerLocation)`
  - `getMobileStoryEntries(story, limit)`
  - `getPersonalStoryEntries(story, charId, location, limit)`
- `App.tsx` 只消费 `StoryEntry`，不在 JSX 中直接拼接 act 展示字段。

验收:

- `src/view-model/storyEntries.test.ts` 覆盖归一化、按地点分组、手机/个人流筛选。
- `npm test && npm run build` 通过。
- 不改 `src/mock/story.ts` 的导出签名和数据结构。

## Phase 2: 视觉系统收敛

目标: 把当前浅色 UI 收敛为单一暖墨/纸色系统，先不引入 FlipBook。

范围:

- `src/styles.css` 的 token 收敛为:
  - 墨色: `--ink`, `--ink-soft`, `--ink-faint`, `--brush`
  - 纸色: `--paper`, `--paper-aged`, `--paper-fold`, `--paper-highlight`
  - 影线: `--line`, `--shadow-page`
  - 字体: `--font-title`, `--font-body`
- 移除强朱砂、蓝绿、霓虹、黑曜石语义 token。
- 保留纸纹 CSS 渐变，不引入图片。
- `.seal` 不删除功能结构，但先改为素墨边框；真正删除可放 Phase 4。
- 大屏、H5、结局卡保持现有布局，只调整色彩、字体、层级和响应式细节。

调整后的限制:

- 不再要求“无红色像素”这类不可稳定验证的断言。
- 可使用低饱和暖色 hue 45-85；状态表达主要靠明度、透明度、纹理和文案。
- 用户可见正文使用 `Noto Serif SC`；图标和按钮仍可保留 lucide 图标。

验收:

- `npm test && npm run build` 通过。
- 375px 手机截图无文字截断，按钮命中区不小于 44px。
- 大屏截图保留纸本史书质感，不能退化成普通白色 dashboard。

## Phase 3: FlipBook MVP

目标: 用统一 `StoryEntry` 实现最小可用的自动分页/翻页展示，先只覆盖大屏地点面板。

范围:

- 新增 `src/components/FlipBook.tsx`。
- 初版 props:

```ts
interface FlipBookProps {
  entries: StoryEntry[];
  pageHeight: number;
  autoFlip?: boolean;
}
```

- 先实现:
  - entries 渲染为统一页内容。
  - 达到页容量后自动翻到下一页。
  - 页码 `第 N / M 页`。
  - `prefers-reduced-motion: reduce` 下退化为淡切或整页直出。

暂不实现:

- 逐字流式落笔。
- 键盘回看。
- 手机 swipe。
- 后台最新页提示。

验收:

- 三个地点面板各自有页码。
- 每个地点的分页数据互不串扰。
- `npm test && npm run build` 通过。

## Phase 4: 流式落笔

目标: 在 FlipBook 内增加字符级渐显，但不改变数据来源。

范围:

- 每个字符包 `<span class="char">`。
- 入场只做 `opacity + translateY`，不做 width 裁切。
- `document.hidden` 时暂停调度。
- 标点后可增加停顿。

实现建议:

- 不使用 `Math.random()` 做不可重复抖动。需要节奏差异时，用 `entry.id + charIndex` 派生 deterministic jitter。
- 字体加载完成前不要做高度测量；可以等待 `document.fonts.ready`，或者先用保守容量分页。

验收:

- 新 entry 到达时能看到逐字浮现。
- reduced motion 下整段直出。
- 构建和测试通过。

## Phase 5: 手机回看和手势

目标: 只在手机故事流上加手动翻页能力。

范围:

- 手机 `world` / `mine` tab 各自保留页码。
- 支持左右热区点击或 swipe，阈值 40px。
- 用户停在历史页时，新内容不丢失；提交自己的行动后回到最新页。

大屏不做手动交互。

## Phase 6: 节点/结局高级动效

目标: 在已有 node takeover 和 card 上加入合书/展开动效。

范围:

- `node-takeover` 改为纸页合书/展开。
- `card` 去掉或素化 `.seal`。
- settlement 可以延长停留，但 mock 环境不要硬等 20-30 秒阻碍测试。

## 不再使用的原计划硬断言

以下断言不作为自动验收标准:

- “页面无任何 hue 落在红(<40)或蓝绿(>100)区间。”
- “无红色像素。”
- “grep token 名称等于 0 即表示视觉合规。”

替代方式:

- CSS token 扫描只作为辅助。
- 以截图人工检查视觉方向。
- 以 `npm test && npm run build` 保证工程正确性。
